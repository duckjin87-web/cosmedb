# CosmeDB — 협력업체 조사 · 방문 · 등록평가 플랫폼

한국콜마 협력생산팀 / 품질보증팀의 신규 협력업체 **조사 → 방문 → 등록평가** 흐름을 하나로 잇는 사내 도구입니다.

> 흩어진 조사 결과를 마스터 한곳에 모으고, 같은 질문을 두 번 하지 않게 만드는 것이 목표입니다.

---

## 무엇을 해결하나

| 기존 문제 | 이 도구의 처리 |
|---|---|
| 조사할 때마다 정보가 흩어짐 | 업체마스터 + 역량 항목 사전에 누적 |
| 다른 건으로 조사할 때 중복 발생 | 조사 설계 시 **기보유 / 재확인 / 신규** 자동 분류 |
| 조사한 조건으로 다시 못 찾음 | 항목코드 기반 조건 조합 검색 |
| 방문 일정 조율이 메일·전화로 흩어짐 | 부서별 가능일 교차 계산 |
| 방문 이후 등록평가로 연결이 끊김 | 상태 전환 시 등록평가 자동 생성 |

## 화면 구성

```
1 업체마스터 ──▶ 2 조사 ──▶ 3 방문예정처 ──▶ 4 등록평가
     ▲                                            │
     └──────────── 조사 완료 시 마스터 갱신 ◀───────┘
```

### 1 업체마스터
전체 업체 목록. 행을 누르면 기본정보와 **최근 6개월 갱신 이력**이 열립니다.
6개월 이전 이력은 흐리게 따로 보관되어, 과거 자료의 오류를 추적할 때만 참고합니다.

### 2 조사
조사 목적별로 한 행씩 쌓입니다. 열은 `조사일 · 생성자 · 상태 · 조사목적 · 대상 · 완료 · 진행중 · 조사대기 · 진행율`.
행을 누르면 대상 업체 목록이 아래로 펼쳐집니다.

조사 생성 방법은 두 가지입니다.

- **마스터에서 업체 지정** — 항목과 업체를 고르면 중복 점검 결과가 즉시 표시됩니다
- **리스트 업로드** — 외부에서 받은 업체 리스트를 붙여넣어 마스터와 매칭합니다

### 3 방문예정처
1행 = 1방문처, 좌우로 긴 대장 형태. 열 그룹 6개를 접었다 펼 수 있습니다.
부서별 가능일에서 공통 가능일을 계산하고, 방문 예정시간을 넣으면 이동 시간과 출발 시각이 나옵니다.

### 4 등록평가
`방문예정`으로 상태를 바꾸면 확인창을 거쳐 평가가 생성됩니다.
평가서 작성은 기존 등록평가 시스템으로 연결됩니다.

## 데이터에 대하여

이 저장소의 데이터는 **모두 더미**입니다.

| 항목 | 내용 |
|---|---|
| 업체 | 30개사, 모두 가상 (`V001`~`V030`) |
| 업체명 | 가온코스메틱, 누리랩 등 실재하지 않는 이름 |
| 대표자·연락처 | 가상 인명 / `010-0000-xxxx` |
| 주소 | 실존 산업단지 도로명 + 가상 번지 |
| 홈페이지·메일 | `example-NN.co.kr` |
| 역량값 | 161건, 기업개요에서 규칙 생성 |
| 방문 건 | 8건 |

실제 데이터로 바꾸는 방법은 [docs/MIGRATION.md](docs/MIGRATION.md)를 참고하세요.

## 알려진 제약

- **저장이 없습니다.** 새로고침하면 초기 상태로 돌아갑니다. 시안 단계이며, 영속화 방안은 [docs/DEPLOY.md](docs/DEPLOY.md)에 정리했습니다.
- **이동 거리·시간은 추정치입니다.** 세종 전의면 기준으로 지역별 대략값을 씁니다.
- **마스터에 사업자번호가 없습니다.** 이 때문에 매칭이 업체명·대표자·주소지 조합에 의존합니다.
- **들어 있는 데이터는 전부 더미입니다.** 업체명·대표자·연락처·주소·홈페이지 모두 가상이며, 실제 협력업체 정보는 하나도 포함되어 있지 않습니다. 실제 데이터로 교체하는 순간 저장소를 **Private으로 전환**하세요.
