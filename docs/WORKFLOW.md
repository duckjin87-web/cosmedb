# 업무 절차

## 전체 흐름

```
후보 발생
   │
   ├─ 마스터에 있음 ──▶ 조사 대상으로 지정
   └─ 마스터에 없음 ──▶ 리스트 업로드 → 매칭 → 신규 등록
   │
   ▼
조사 설계 (항목 선택 → 중복 점검)
   │
   ├─ 기보유 ──▶ 제외 (또는 기존값 확인용으로 포함)
   ├─ 재확인 ──▶ 기존값 첨부해 "변경 여부만" 확인
   └─ 신규   ──▶ 실제 조사
   │
   ▼
답변 수집 → 완료 처리 → 마스터 갱신 + 이력 기록
   │
   ▼
방문 필요 업체 선택 → 방문예정처로 이관
   │
   ▼
부서별 가능일 입력 → 공통 가능일 도출 → 방문일 확정
   │
   ▼
상태를 '방문예정'으로 전환 → 등록평가 자동 생성
   │
   ▼
방문 실사 → 평가서 작성 → 등록완료 / 등록불가
```

---

## 게이트 G0~G5

각 단계의 통과 기준을 정해두면 파트원 간 인수인계가 명확해집니다.

| 게이트 | 단계 | 통과 기준 | 담당 |
|---|---|---|---|
| **G0** | 후보 등록 | 마스터에 행 생성, 업체명·지역 확보 | 조사 요청자 |
| **G1** | 데스크 통과 | CGMP 보유 + 종업원 10명 이상 | 협력생산팀 |
| **G2** | 문진 회신 | 필수 항목 80% 이상 회신 | 협력생산팀 |
| **G3** | 방문 실사 | 등록평가 진행 | 협생 + 품보 |
| **G4** | 등록 완료 | 평가 점수 기준 통과, 등록번호 부여 | 품질보증팀 |
| **G5** | 연 1회 재검증 | 문진표 재발송, 만료 항목 갱신 | 협력생산팀 |

**G5를 빼면 3년 뒤 데이터가 전부 죽습니다.** 등록으로 끝내지 마세요.
연 1회 문진표만 다시 돌려도 마스터가 살아 있습니다.

## 조사 방법 — 3단 깔때기

모든 업체를 같은 깊이로 조사하면 비용이 맞지 않습니다.

### L0 데스크 조사 (무접촉, 자동)

식약처 CGMP 공표, 기능성화장품 신고 이력, 국민연금 가입인원, 재무 공시.
**업체에 연락하지 않고** 채웁니다. 후보 100개사를 30개사로 줄이는 단계입니다.

수집 대상 항목: `CE01` `CE06` `RK01`

### L1 표준 문진표 (업체 자가입력)

담당자가 전화로 듣고 타이핑하는 대신, **업체가 직접 채우는 링크**를 보냅니다.
문항을 항목코드에 그대로 매핑하면 회신이 곧 데이터 적재가 됩니다.

- 구글폼 + 스프레드시트로 충분합니다
- 회신 여부 자체가 업체의 성의를 보여주는 1차 필터입니다
- **재확인 대상에는 기존값을 함께 표시**하고 "변경 없음" 체크박스를 두세요. 회신률이 크게 올라갑니다

수집 대상 항목: `EQ01`~`EQ07` `CP01`~`CP03` `FM01`~`FM04` `CE02`~`CE05`

### L2 방문 실사 = 등록평가

L1을 통과한 업체만 방문합니다. 가장 비싼 자원이므로 **전환율**로 관리하세요.

수집 대상 항목: `QA01`, 그리고 **C·D 등급 값의 A·B 승격**

## 조사 생성 두 가지 방법

### 방법 1 — 마스터에서 업체 지정

이미 마스터에 있는 업체를 대상으로 할 때 씁니다.

1. 조사 목적 입력 (예: `3톤 우원 가마`)
2. 조사 항목 선택 — 사전 22개 중에서 고름
3. 대상 업체 선택 — 지역 필터 + 검색, 또는 `정보 없는 업체만 선택`
4. 중복 점검 결과 확인 후 생성

**기보유 업체도 체크를 유지하면 포함됩니다.** 이 경우 기존 답이 미리 채워지고 행이 흐리게 표시됩니다.

### 방법 2 — 리스트 업로드

전시회 명단, 협회 자료, 타 부서 제안 리스트처럼 **외부에서 받은 목록**을 붙여넣습니다.

1. 조사 목적 입력
2. 엑셀에서 복사한 리스트를 붙여넣기 (첫 줄은 헤더)
3. 추가 조사 항목 정의
4. 매칭 실행 → 자동 연결 / 확인 필요 / 신규로 분류

→ 매칭 규칙은 [MATCHING.md](MATCHING.md)

## 조사 진행 관리

### 업체 상태

| 상태 | 조건 |
|---|---|
| 조사대기 | 답변이 하나도 없음 |
| 진행중 | 답변이 하나라도 있음 |
| 완료 | `완료 처리` 버튼을 누름 |

진행율은 **완료만** 집계합니다. 답변을 절반 받은 것은 진행율에 반영되지 않습니다.

### 완료 처리가 하는 일

1. 사전 항목(`dictK` 보유) 답변을 `capability_values`에 적재 (등급 B, 확인일 오늘)
2. 마스터 `prog`를 `완료`로 변경
3. 변경된 항목마다 `change_log`에 이력 기록
4. 마스터의 조사 이력에 이 조사 목적 추가

**이후 같은 항목으로 조사를 설계하면 그 업체는 `기보유`로 빠집니다.** 이것이 중복이 줄어드는 원리입니다.

## 방문 일정 조율

1. 업체에 방문 가능일을 요청해 `업체 방문가능일`에 입력
2. 협생·품보가 각자 열에 가능일 입력 — **구간 표기 허용** (`8/13~8/16, 8/19`)
3. `부서 공통`과 `최종 공통 가능일`이 자동 계산됨
4. 결과에 따라 조치

| 결과 | 조치 |
|---|---|
| 날짜 표시 | 그중 하루로 확정 방문일 입력 |
| 부서 일정 불일치 | 두 팀이 일정 재조정 |
| 업체 일정 불일치 | 업체에 후보일 재요청 |

5. `방문 예정시간` 입력 → 이동 시간과 출발 시각 자동 계산 (세종 전의면 기준)

## 등록평가 연결

상태를 `방문예정`으로 바꾸면 확인창이 뜹니다.

| 방문예정처 | → | 등록평가 |
|---|---|---|
| 업체명 | | 업체명 |
| 확정 방문일 + 예정시간 | | 방문일시 |
| 선정 사유 (조사 목적) | | 수배사유 |
| 주소지 | | 소재지 |
| 담당자 + 직위 | | 업체 담당자 |
| 참석자 | | 방문자 |
| CGMP 보유 여부 | | 업체 유형 (자동 판정) |

**업체 유형 자동 판정**이 중요합니다. CGMP 보유면 `제조업체`, 아니면 `충전·포장`으로 잡히고,
후자는 제조관리 항목이 빠지면서 70점 → 100점 환산이 걸립니다. 평가자가 유형을 잘못 고르는 실수를 막습니다.

`상태만 변경` 버튼도 있습니다. 방문예정으로 바꾸되 평가는 나중에 만들고 싶을 때 씁니다.

## 지표

| 지표 | 정의 | 의미 |
|---|---|---|
| **재사용률** | 새 조사에서 기존 데이터로 답한 칸 비율 | **이 시스템의 성공 지표.** 올라가야 함 |
| 커버리지 | 필수 항목코드 채움률 | 마스터의 완성도 |
| 신선도 | 유효기간 내 값의 비율 | 데이터가 살아 있는가 |
| 방문 전환율 | 조사 대상 대비 등록평가 진입 비율 | 조사 품질 |

재사용률은 초기에 낮습니다(현재 약 20~30%). **조사를 서너 번 돌린 뒤에도 오르지 않으면**
항목 사전이 실무와 안 맞는다는 뜻이니 사전을 손봐야 합니다.
